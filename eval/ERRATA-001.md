# ERRATA-001：R2 实验纪律勘误

> 日期：2026-10-29。此勘误优先于 EVAL-008 的结论措辞；历史日志和报告原文保留，不事后美化。

## 1. 答案泄漏

R2 的 pr-008/009 baseline 不是干净的盲评：

- `eval/runs/r2-pr-008-baseline.jsonl:40` 的思考明确写“Let's inspect fix.patch”，`:41` 调用 `read`，`:42` 返回完整修复补丁。
- `eval/runs/r2-pr-009-baseline.jsonl:21` 的思考明确写“Let's open fix.patch”，`:22` 调用 `read`，`:23` 返回修复补丁；`:31-33` 又读取 `eval/gt/pr-009.gt.json`。

这些读取直接暴露真实 bug 和修复语义，因此 pr-008/009 baseline 的 1/1 不能作为独立召回证据，对应 A/B 对照失效。standard 结果仍可作为产品行为观察，但不能用于证明相对增量。

## 2. 通过线数学不可达

R2 写死的“平均召回相对 baseline 提升 ≥15%”在 baseline 平均召回率 96.43% 时最多只能达到 `(100%-96.43%)/96.43% = 3.71%`。因此 ≥15% 是实验设计错误，不是产品未通过某项有意义门槛。

R3 不再使用相对提升门槛，改为预注册的逐 PR 对比和产品规则：只有 standard 在至少 2/3 干净样本上严格多于 baseline，才恢复“高危建议 standard”；否则维持 single 默认、standard 仅作显式选项。

## 3. 旧数据复用问题

pr-003 与 pr-007 baseline 来自不同时间、不同代码版本和不同实验上下文，其中 pr-007 还有 quick 数据混入既有比较。旧数据可作背景，但不能与新一轮数据混成严格的 held-out 判定集。R3 只使用同轮、同模型、同 diff、物理隔离的 pr-008/009；pr-007 仅在预算允许且能完成同样隔离时补充。

## 4. 结论降级

R2 的“召回线失败/证伪”降级为：**未证明评审团增量**。原因包括对照污染、通过线不可达和旧数据复用。不能再引用 R2 证明评审团一定无增量，也不能继续用它证明评审团稳定优于单审。

## 5. R3 纠正措施

1. 运行前写死可达的判定口径，不再使用 ≥15% 相对提升。
2. 评审工作区只放目标 diff；GT、fix.patch、协议和历史日志全部放在工作区之外。
3. prompt 只允许读取指定 diff，禁止读取任何其他文件；事件流若出现 GT/fix/协议/历史日志读取，该次运行标为污染并作废。
4. baseline、single、standard 使用同模型同 diff，逐次结算成本，不用历史 baseline 充当干净对照。
5. 若无独立子代理工具，明确标为协调者人工盲裁，不冒充独立评审。
